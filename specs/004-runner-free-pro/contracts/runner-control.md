# Runner Control Contract (protocol v2)

## Existing transport

`POST /api/runner/heartbeat`, authenticated by device bearer credential; preserve established polling rate limit (currently12 requests/min). Do not expose this credential to dashboard/MCP responses. `Cache-Control: no-store`; validate size/schema and report actual states only for assigned sessions. For old clients return a structured update-required response before admitting new-policy output; never silently omit watermark/admission enforcement.

Request v2: `protocolVersion`, `capabilities` (`admissions`, `destinations`, `drain`, `local_schedule`, `runner_presentation`), device/OS/version, config acknowledgment, and observations keyed by admissionId+generation. Observations include session state, occurrenceId, per-destination state (`connecting|streaming|retrying|failed|stopped`), sanitized error code, currentClipId/progress/finishing, and terminal output-closed evidence. Reject foreign IDs, stale generation or fabricated owner identity without changing occupancy.

Response v2: `serverTime`, monotonically increasing configRevision, signed owner-benefit snapshot, assignments, desired-state commands, optional signed seven-day occurrence cache, branding profile, and protected execution secrets only for this authenticated assigned device. Secrets are not echoed by acknowledgment. An assignment carries admissionId/sessionId/generation/mode/controlMode/overlay source/destinations/resolution/fps/startPolicy/stopPolicy/schedule occurrence IDs and presentation bootstrap. Return only changed cached nonsecret config where practical; heartbeat must not resend asset bytes.

Signed snapshot/permit binds issuer, ownerId, runnerId, sessionId where applicable, revision, generation, target IDs/hash, source revision, issuedAt, known paid validUntil and horizon. Official Runner verifies signature and identity before execution. Unknown/revoked signatures prevent new starts. No monthly consumption amount exists. Known expiry blocks paid starts locally; server sends baseline capabilities at reconnect. Unscheduled Pro active output follows captured expiry transition.

## Shared admission service

Dashboard start/stop, MCP control, heartbeat and local scheduled-start reconciliation use the same owner-locked service. Dashboard cannot claim success means output is already live: response includes `accepted`, `applied=false`, admissionId, current/desired state and configurationRevision. Free denies second nonterminal owner admission and >1 target with `RUNNER_CONCURRENCY_LIMIT` / `RUNNER_TARGET_LIMIT`; Pro permits multiple.

Manual Free starts require a centrally reserved admission. Pro signed scheduled occurrences preauthorize local starts for the assigned Runner and stable occurrence generation; reconcile their admissions on heartbeat without applying Free commercial limits retroactively. An expired/revoked known benefit does not authorize new scheduled starts. Device health loss marks uncertainty and never itself frees the slot; supported Free lease expiry initiates bounded local drain and later permits recovery.

Matching stop acknowledgment releases occupancy only when all generated/live-forward outputs have closed. A disconnect, deleted row, requested stop, revoked credential, expired heartbeat or detached input is not equivalent. Deleting/unlinking active devices requests shutdown first; if offline, retain owner-scoped uncertain tombstone. UI guides reconnection/shutdown and does not offer unconditional force-release. A never-dispatched reservation can be canceled; a lost acknowledgment requires idempotent replay/reconciliation.

## Graceful and immediate stopping

Commands: `start`, `drain`, `stop_now`, `pause_automation`, `resume_automation`, `refresh_config`; all correlated by admission+generation+commandId. A normal manual or scheduled stop drains generated playback. If no generated clip is playing, stop promptly. Live forwarding has no Clipify clip boundary; owner stop closes it promptly. Scheduled control is not offered for Live fallback.

Drain disables next-clip advancement, pending crossfade and replacement playback. Browser returns progress and terminal acknowledgment only for the active generation. The Runner closes target outputs and persists its terminal journal before acknowledging stop. Drain watchdog: stop after60s without progress beyond the end boundary or300s total overrun. `stop_now` intentionally interrupts. Replayed/stale commands never start/stop a newer execution.

## Faults and observability

Expose safe states/errors: authentication/permission denied, update required, stale revision conflict, invalid target, missing credential, same-Runner overlap, device offline/uncertain, local cache invalid, source unavailable, output retrying/failure, playback timeout and persistence failure. Failed saves retain last persisted config. All-target failures are visible; recovery remains generation-bound and cannot reopen after stop. Redact bearer tokens, overlay/presentation secrets, stream keys and full credential-bearing FFmpeg output before logs/status/audit.

## Compatibility

Keep old mode/storage values. Legacy scalar target reads resolve one destination; first supported edit normalizes it transactionally. After normalization, the named target is authoritative. Dashboard and MCP metadata edits preserve its current endpoint/provider/credential and synchronize only the scalar compatibility shadow. An explicit credential replacement/clear or endpoint change is required to alter that target; ambiguous scalar edits of shared/multiple target configuration return a safe conflict. Additive safe MCP status fields do not expose credentials. Reject unsupported advanced operations explicitly. Existing desired/actual enum can stay unchanged; detailed admission/output state is additive. Release order: schema workflow-managed migration, compatible app support, v2 Runner artifacts, then enable new-policy starts after capability negotiation. Document update-required behavior; never pretend old binaries passed new guarantees.

## Signature key configuration

Proposed server secret `RUNNER_EXECUTION_SIGNING_PRIVATE_KEY` signs bundles using a key ID. Official Runner distributions trust configured public verification keys; tests generate ephemeral key pairs and never read deployment secrets. Rotate verification keys with a compatibility overlap covering issued snapshot horizons. Signatures bind exact resource/revision/generation and cannot substitute for server admission/authorization. Private keys and signatures are excluded from public/customer billing records. Provisioning a production key is a later deployment configuration action, not performed during planning.

## Reconciled Free lease and terminal recovery (U1)

Free admission permits carry leaseId, admissionId, generation, issuedAt and leaseExpiresAt, signed and bound to owner/device/session/target set. Renew on authenticated existing heartbeat at the established polling rate; extend expiry only after the owner-locked transaction persists the new deadline. Lease TTL is 300 seconds. Runner uses server-time anchoring and a monotonic deadline, persists lease state, rejects replay/foreign/tampered leases and never resets validity by restarting or rolling back the wall clock. Offline restarts require fresh renewal for Free output. Pro cached scheduling remains separately authorized by its signed benefit/cache horizon.

At Free lease expiry enter irreversible drain for that generation: no next clip, all targets closed no later than expiry+300 seconds, or after 60 seconds without clip progress. Live forwarding closes promptly. Server retains occupancy through the final issued expiry+305 seconds unless a matching terminal ACK arrives earlier. A concurrent renewal/release is owner-locked; revoked/tombstoned generations cannot renew or restart. An outage is an exceptional bounded stop, not a monthly quota. Show lease expiry/recovery state and explain that Free needs periodic Clipify connectivity. Unlimited hours do not promise indefinite disconnected operation.

Unlink/delete immediately disables configuration, new starts and lease renewal. Keep a tombstone and a hash of the former bearer token usable only at proposed POST /api/runner/terminal for schema-bounded, rate-limited, generation-bound terminal output-closed acknowledgments. It returns no assignments, config or secrets, cannot renew or start, and is removed after reconciliation/lease recovery. Invalid/foreign/stale ACKs cannot release another generation. Old clients without negotiated lease enforcement require explicit matching terminal reconciliation; heartbeat age alone never releases them.

Clipify can enforce these rules in supported official clients. A user modifying their local Runner could ignore them; the service cannot remotely prove their independent RTMP process stopped. No anti-tamper/DRM guarantee is claimed.

## Multistream capture

A Start captures a versioned encrypted destination set. Pro manual starts use a fresh nonce-bound `pro_broadcast` permit; its short acceptance window bounds starting, while accepted manual execution continues until normal Stop. Free uses `free_lease` renewal and its existing bounded expiry/drain policy. Both sign the complete canonical target hash, source and admission identity. A Free guard never accepts a paid permit, and a Free execution never accepts multiple targets. Updates to saved targets affect future admissions. Reject device/source reassignment until output closure so the original device keeps receiving Stop commands. Compatible targets share one capture/H.264-AAC encode; separate bounded stream-copy queues perform all delivery on the user's PC.

### Cached scheduled execution authorization

Local offline dispatch uses a distinct signed `scheduled_execution` purpose with explicit `cacheAuthorization: true`, Pro policy, owner/device/session/admission/generation, nonce, immutable occurrence ID/start/end, source and configuration revisions, canonical target hash and `executionPayloadHash`. A normal execution consumer does not accept this purpose. The authorization lasts at most seven days and is also bounded at issuance by known paid expiry; accepting new output requires the original half-open window and a verified cache elapsed-time anchor. Already accepted output keeps its original end and bounded drain. The private payload digest binds source credentials and capture settings in addition to the separately canonicalized destination set. Read-only calendar metadata is never an execution authorization. Owner-locked future issuance, protected key-reference storage, signed elapsed-time restore and official native watchdog dispatch now have scoped execution evidence. Revocation preserves future authorization tombstones; only physical attempts drain. Matching unused-authority closure cannot stop another physical execution. New cached starts require capability negotiation; old devices receive no cached execution authority. Complete milestone qualification, continuous adjacent-window transitions and final restart/override journeys remain open; this contract does not claim release readiness.
