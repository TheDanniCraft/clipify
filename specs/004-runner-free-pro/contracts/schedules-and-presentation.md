# Schedule, Destination and Presentation Contracts

## Dashboard and shared resources

Existing `/dashboard/runners/[id]` gains destination management, Clip playback / Live fallback behavior labels, Manual / Scheduled controls, and standby/attribution preview. Keep matching permissions for configure/control; owner capabilities determine availability. Shared owner-scoped resource services are called by authenticated server actions and supported MCP configuration/control contracts. Do not invent separate MCP privilege or billing logic. Extend existing MCP workflow schema/catalogue projections when fields are supported; all documented entry points use common validation/revisions.

Config mutation envelope: resource ID, `expectedRevision`, changed fields; owner comes from trusted resource/principal. Return new revision and safe projection on success. On `CONFLICT`, re-read and let user reconcile rather than overwrite. Permission denial leaves state unchanged. Check this at each Next Server Action / route entry point; rendered controls are not authorization. Avoid client `Promise.all` for Server Action parallelism per installed Next guide.

## Destinations

Create/update/list/delete named YouTube, Twitch and custom RTMP records; editing credential supports keep/replace/explicit clear. Return `credentialConfigured` plus sanitized host/provider, never plaintext key. Server validates schemes and size but does not connect to arbitrary RTMP URLs: connection originates from the user's Runner. Free may retain multiple saved historical targets after downgrade but can configure/select only one active target. Pro selects multiple targets for one broadcast; failures/retries are displayed separately. Target deletion while referenced is rejected with reference details; remove its future event/session references in an explicit owner-authorized edit first.

## Planner

Agenda uses `useAgenda({events,view:'week',onEventCreate,onEventMove,onEventResize,onEventSelect,onEventDelete})`. Configure a full-day grid; modal editor exposes title, IANA timezone, one-time/weekly recurrence, dates/weekdays, start/end, owned overlay/playlist source and destination selection. Equivalent keyboard/form/list actions and accessible conflict messages are mandatory. Timezone conversion is explicit at adapter boundary, not implicitly browser-local.

Overlap check runs transactionally against the saved event set; optimistic UI rolls back to persisted events on failure. Events identify Runner/session; same-Runner overlapping windows are rejected even with different targets. Adjacency merges equal normalized source/target sets, otherwise waits for draining and skips expired next windows. All-day uses local midnight boundaries and can last 23, 24 or 25 elapsed hours. Timed broadcasts can span multiple days and weeks. Live fallback has no Scheduled control. Empty target/source, invalid date/timezone, malformed recurrence, zero/negative duration, weekly self-overlap and unauthorized references are rejected.

Local scheduler evaluates every<=5seconds on an awake PC; generated start must be observed within30s under fixture conditions. It restores signed cache and occurrence journal, skips ended windows, starts the remaining active window once, and persists manual suppression. Pausing automation prevents future occurrences and allows current event to finish; explicit stop suppresses the current occurrence. PC sleep/offline is shown, not marketed as hosted execution. At cache horizon expiry show synchronization-required; never invent future events.

## Runner presentation

Proposed dedicated `POST /api/runner/presentation` authenticates Runner and assigned active admission, returning a short-lived opaque bootstrap URL/credential bound to that session/generation. An authenticated `/runner/presentation/[sessionId]` renders a Runner-specific wrapper around existing OverlayPlayer; ordinary `/overlay/[overlayId]` remains ordinary. Consume bootstrap without leaving long-lived keys in URL/logs; use scoped HTTP-only presentation session or signed browser-local context. Opaque presentation credentials never appear in MCP/public projections. GET/POST handlers follow installed Next Web Request/Response conventions and await dynamic params.

Policy returns attributionRequired, allowed corner and standby appearance. Free cannot suppress required attribution through query flags or inherited paid settings. Render generated playback/fallback/standby attribution in the frontend; live RTMP forwarding bypasses that rendered surface. Default corner bottom-right; all four positions, same readable size/contrast and preview output. Pro may opt into attribution.

Standby renders only when an active broadcast has no playable content or awaits playback, never outside event windows. Customize logo, background color/image, max160-character plain-text message and optional next broadcast time in saved timezone. Pro expiry retains profile data while renderer uses baseline appearance; active output is not forcibly disconnected.

## Assets

Owner-authenticated asset POST handler (route instead of larger Server Action bodies), max2MiB PNG/JPEG/WebP, decode/dimension verification and stripped re-encode. Assets are stored owner-scoped as bytea/metadata; authorized presentation serves normalized MIME with `nosniff`, never HTML/SVG. Asset/branding revisions control cache busting. Decode failure, oversized body, unsupported format or storage failure returns an explicit error and preserves previous profile reference. Do not fetch arbitrary remote image URLs. Use already installed server image tooling where compatible; verify runtime and add no external service.

## Reconciled identity, active controls and multi-day time (I1/A2)

Event id is stable through create/move/resize/edit, using installed onEventMove(id,start,end), onEventResize(id,start,end), onEventDelete(id). occurrenceId combines eventId and an immutable recurrence anchor; configurationRevision is separate. One-time occurrence retains identity when moved; weekly occurrence retains its original recurrence anchor when edited. Never create new occurrence identity merely by revision changes or visual segmentation. An explicit new event has a new id. Suppression survives revision changes and restarts.

At start, atomically capture occurrence start/end/source/destinations. From activation until the original end (including manually stopped/suppressed time), or until terminal drain completes if later, reject move/resize/delete and configuration changes affecting that occurrence with ACTIVE_OCCURRENCE_LOCKED. No arbitrary pre-start lockdown. Future occurrences may be changed separately, retaining the locked active snapshot; do not delete a series containing a locked occurrence. Validate server-side across dashboard/MCP, and render active segments read-only.

User Stop gracefully finishes the current clip and atomically switches control to Manual, preventing scheduled restarts. Stop now remains the explicit emergency action. Manual Start is disabled in Scheduled mode. Explicitly saving Scheduled mode again authorizes a still-active event after the previous output closes, retaining its original end; an ended event is never replayed. Pausing automation prevents future starts while the current execution finishes its window. The agenda is the single schedule browser, with a Live badge only for a fresh matching streaming report. It remains accessible in Manual mode; saving an event alone does not enable scheduling. Selecting Scheduled keeps the configuration editor open and disables the Schedule button with a nearby save prerequisite until configuration is saved. The agenda does not save or enable the parent configuration.

One-time events store explicit local start and end dates/times and can span days/weeks. Weekly events store start weekdays and endDayOffset 0–7 with local times, reject self-overlap/other same-Runner overlaps, and may occupy a complete calendar week when boundaries exactly touch. No timed 24-hour cap. All-day uses start local midnight to exclusive end-date local midnight; DST can yield 23 or 25 elapsed hours. Gap boundary skips the occurrence with explanation, repeated boundary uses the first instant. UTC instants determine elapsed duration; local dates determine recurrence.

Agenda week is a viewport, not a scheduling limit. Installed timed getEventsForDay selects starting dates only: adapter projects each intersected day into visual segments with segmentId -> logical eventId/occurrenceId, preserving true bounds. Move translates the logical interval; resize changes its actual boundary, never a clipped viewport boundary. Editor exposes start/end dates and times. Mobile uses day view plus the same accessible editor/list and navigation. If gesture projection is ambiguous, use the editor instead of guessing. Cache expansion includes an already-active long event whose start predates the seven-day horizon; include its full end. Adjacent matching windows, including exact midnight boundaries, remain one execution without a stop/reconnect; different targets follow existing drain policy.

## Reconciled readable translucent attribution (A1)

At reference output 1920x1080 use two 56px semibold text lines (line-height 64px), a 112px logo, 12px gap, 24px edge inset and a 128px minimum text block. Scale all dimensions uniformly with output height; no theme-dependent shrinkage. Text/logo opacity is fixed 0.85; a compact backing has fixed 0.65 opacity with a dark outline/shadow. The actual light-frame check measured1.69:1 with the initial0.25 backing, so the shared backing is strengthened to preserve the unchanged4.5:1 minimum while remaining translucent; foreground size/opacity stays unchanged. Use contrasting text/outline maintaining a tested 4.5:1 text contrast on the fixture set of light, dark and busy frames. Free cannot change opacity/size or hide it. At a 360px-wide 16:9 preview, text is 10.5px and the two-line block is 24px high; require readable, unclipped branding. These initial fixed dimensions must be visually reviewed before accepting the UI; adjust the shared contract/fixture together if needed. Overlay title height is a visual reference, not an unbounded user-controlled size input.

Preferred corner defaults bottom-right. Use actual title/progress/theme decoration rectangles plus 12px clearance to avoid occupied overlay regions. Outset shadow bounds conservatively include 1.5 times the computed blur radius plus spread/offset at the actual element scale; inset shadows do not expand occupied bounds. Search within the preferred corner, then other corners in deterministic order, then free edge positions; expose actual placement in preview. If no valid region exists, preview reports the collision and requests overlay layout adjustment; saving/starting a new conflicting generated configuration fails clearly rather than hiding, shrinking or covering overlay UI. Standard themes must have a valid position. Test all four preferred corners and dynamic title visibility with the same renderer in preview/output.

## Fresh generated-content startup measurement

The capture stream initializes before playback to preserve the first source frames. Playback advances a Runner-only content epoch and reports standby/loading/playback/settled-empty state. Each required-attribution measurement binds epoch, phase and clip ID. Runner title/channel/timer panels reserve their identical final bounds invisibly before delayed entry, without changing ordinary overlay timing. Native generated output waits for a fresh ready epoch and matching measured layout (or clean paid layout) before opening any encoder/destination. Blocked layout returns a normal configuration refusal and closes capture; it does not throw a business error. Active live forwarding remains outside the generated surface.

### Effective appearance refresh

`GET /runner/presentation/{sessionId}/policy` uses the existing presentation-scoped cookie, validates the current matching active execution and returns only executionGeneration, attributionRequired and current validUntil with private/no-store caching. It resolves the authorized owner's current Runner benefits and saved attribution choice; revoked/foreign identities return a normal403. The mounted generated surface refreshes every<=30seconds and before a known end. A renewed deadline replaces only appearance state, keeping the video/admission/generation intact. A failed or malformed refresh keeps the last known finite expiry and mandatory branding returns when it elapses. Captured stream authority, source and targets are unchanged.
