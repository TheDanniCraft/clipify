# Data Model

No new database tables or generated migrations in v1. Use existing creator authorization, Twitch clip cache and cache namespaces. Never repurpose Runner `stream_sessions` as creator broadcast history.

| Entity                | Fields and validation                                                                                                                                                                                                       | Lifetime / relationship                                                                                                                                                              |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CreatorContext        | server-resolved creatorId, principal, organization, current permissions                                                                                                                                                     | request-local; all query/result/cache keys bind creator                                                                                                                              |
| InventoryQuery        | title trimmed max 200 chars; optional category ID; ISO startedAt/endedAt; nonnegative integer minViews; nonnegative finite duration bounds; newest/most_viewed; page >=1; pageSize 1..50 default25; timezone validated IANA | shareable URL state; dates normalized once, start inclusive/end exclusive                                                                                                            |
| KnownClip             | existing TwitchClip validated schema; ID/broadcaster, title/category, createdAt, views, duration, thumbnail, optional videoId/vodOffset                                                                                     | existing crawler/cache; not an owned copy of media                                                                                                                                   |
| AvailableBroadcast    | id, broadcasterId, optional streamId, title, createdAt, durationSeconds, thumbnailUrl, providerUrl                                                                                                                          | existing `TwitchCacheType.User` namespace `broadcasts:<creator>:<cursor>`; value.fetchedAt controls five-minute freshness, existing expiresAt cleans after24hours for stale fallback |
| InventoryPage         | items, totalKnownMatching, page/pageSize, snapshot, syncComplete, freshness                                                                                                                                                 | immutable response for one query; reject older client response generations                                                                                                           |
| Selection             | ordered unique IDs (1..50), creatorId, filter/stream fingerprint                                                                                                                                                            | browser-only; retain on request failure; clear on scope changes                                                                                                                      |
| ClipExportManifest v1 | version, exportedAt, creatorId, selected IDs, public clip metadata, entries with filename/variant/bytes/status/reason                                                                                                       | ZIP-only; max 1MiB; no auth data or source download URLs                                                                                                                             |
| Export summary        | included request-position indices and skipped index/reason/retryable arrays, bounded to 50                                                                                                                                  | response header, at most 16KiB encoded; no user titles/URLs in headers                                                                                                               |

Export state: idle -> preparing -> package-ready/download-initiated or partial/download-initiated; preparing -> failed or cancelled. Package readiness is not disk-save confirmation. Retry failed constructs a new request from retryable unsuccessful IDs, retaining valid original scope. Completed successes are not silently resubmitted. All failure produces no package. Creator change invalidates pending state/results and aborts browser requests.

Permission addition: `clips:export` in the existing permission registry and owner/operations/contentManager roles; add `creator:read` to contentManager so that its new export grant can satisfy the read-plus-export contract. Custom roles receive nothing automatically; analyst and billingManager do not receive media export. Inventory/stream read requires `creator:read`; existing team/agency lifecycle and entitlement rules remain authoritative. Permission storage uses existing role JSON; no auth-schema changes expected.

## Portrait channel preset

Reuse user_content_states with content_key=clip-portrait-layout:v1 and the creator as user_id. State contains a version1 validated layout: Full/Stacked mode, camera share0.2–0.5, normalized gameplay/camera crop rectangles, and up to3 metadata layers with bounded percentages/font sizes. It stores field names rather than resolved clip metadata. Read uses creator:read; upsert uses creator:update. Existing account export/removal includes this state. No Drizzle schema or generated migration changes.

Paired templates supersede separate format identities: each clip-layout-template:v2:<id> JSON state contains name, a compatibility composition, and validated compositions.desktop/compositions.mobile. Existing single-format entries read with a starter counterpart and preserve their saved format. The clip-layout-default:v2:template key identifies one default collection; old per-format default keys remain readable. New overrides use clip-layout-override:v2:<templateId>:<clipId>:<format>; historical unsuffixed overrides are read only for their matching format. Reset deletes only the requested format, while template deletion removes all its own format overrides.
