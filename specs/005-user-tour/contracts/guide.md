# Interaction contract

The launcher uses a HeroUI progress ring above the original feedback button. The checklist has a short title, four accordion sections and plain task rows. Only one section expands. A row is clickable across its title/action area; its checkbox shows completion or an indeterminate active state. Replay is an icon/action on that same row. No visible status subtitles, chooser control, completion card, persistent help paragraph or browser-storage footer. Guide copy uses no em dash.

A checkbox request opens a separate HeroUI popover anchored to it. Cancel and a second request do not change progress. Only confirmation records a manual skip; unchecking restores the task. Popover focus takes priority over deferred launcher focus.

Starting/replaying never changes pages. A task on another page highlights the actual Dashboard link, tab, edit control or app-menu action. Creation replay reaches Add Overlay, regardless of existing completion. Only the user's normal Add action creates a resource. Within a journey, successful steps continue naturally; explicit acknowledgement of current/default settings completes the guide without changing the resource. Native Save controls remain unchanged.

Consent settings hide/pause guidance. Expected preview and unguided clip dialogs temporarily suspend it. The explicitly guided playlist picker retains its steps inside the owning modal focus scope. Native menus preserve their semantics and focus. Missing controls and unrelated navigation pause with a short recovery message, without returning the user to another page. Support introductions point to the real widgets; using one pauses the guide so its normal form/dialog remains usable.

Account progress persists in PostgreSQL. Browser clearing and reauthentication preserve completion, skips and minimization. Existing owned setup is recognized without showing a new-user popup. Clipboard success is required before external instructions; finishing them is self-reported learning completion, not verified delivery.

The launcher names the current or most recently active section and shows that section’s percentage in every state. Persist the section ID with account progress. Filters appear only in the core Choose your clips task. Personalization contains only styling; confirming the current/default look completes the guide without changing the saved style. Starting styling inside Theme Studio begins at the editor. Resuming a styling checkpoint elsewhere highlights normal navigation through overlay settings and Customize Overlay Style before returning to that checkpoint. Save steps expose Back to review filters or styling, without changing the app’s Save action. Styling highlights the workspace including its live preview and summarizes color, font, component and effect controls rather than requiring every setting to be changed. Subtasks remain flat.

Opening a native HeroUI select/color popover keeps the spotlight dimming visible. The portal appears above it and remains keyboard/pointer accessible; dismissing the popover restores guide controls without a screen-wide flash. Progress is section-wide with equal task weights: completed or skipped tasks count fully, the active unfinished task begins with half credit and advances with its steps up to 95% task credit. Replay of a finished task adds no credit. Completion remains based on saved actions, explicit confirmation or skip, not the visual estimate.

Guide controls are actual HeroUI Buttons rendered through a React portal in the Driver popover; Driver’s native action buttons are disabled. The engine permits Back from every action index after the first, with no per-step opt-in. Going back across an entry-page boundary highlights the corresponding normal app control, such as Theme Studio’s Back to Overlay Settings button. The ring and launcher accessible name always use section percent, including while idle or after completion. Task counts remain in the accordion.

Playlist clip guidance follows Add Clips, optional search, selection including pagination, native Add selected clips, arrangement and Save Playlist. Search inputs use HeroUI secondary styling in both clip pickers. Confirming a nonempty selection advances to arrangement automatically; it updates the draft, not completion. Acknowledged saves and guided current/default confirmations complete the guide; only explicit checklist skips record a skip. Closing a picker pauses the current action, and resume teaches reopening it through Add Clips. Back from modal search points to the native Cancel control before returning to entry. Guide controls stay in the owning modal; native modal/grid keyboard and scrolling stay usable. Selecting all normalizes React Aria’s all token to actual clip IDs, preserving selection across pages.

Automatic continuation is limited to tasks in the same section. The final task never launches another section; optional sections require a separate explicit start. No completion card or forced cross-section tour is added.

Use a playlist follows the actual Overlay Type. Selecting Playlist advances to the playlist selector without another Continue click. A non-playlist source keeps or restores the source step, disables invalid forward acknowledgement and does not pause the flow. Back to an already correct source remains reviewable. Native Save still controls settings persistence; a guided current-settings confirmation completes only the lesson. Modal hints prefer a side placement so native Cancel remains accessible; only the guide’s own relocated popup has transient outside-modal inert/aria-hidden flags repaired. Other modal/consent roots retain their own state.

Welcome start/dismiss are validated account-scoped events. Start accepts only an allowed guide location and begins the first unfinished core task. Event acknowledgement includes the durable expertAwardedAt timestamp when earned; callers cannot set an award timestamp through an event. All 15 current tasks must be completed; skips never qualify. The server stamps expertAwardVersion=2 for this all-guides policy, and old core-only awards are ignored. Badge resolution reads the account content-state timestamp and uses the catalog’s automatic graduation-cap presentation.

Guided terminal confirmations (Use current settings, Keep default look, Keep current name/playlist) complete the guide and remove an earlier skip. They do not mutate or claim saving the native resource. Only explicit task.skip/checklist confirmation records a skip. Display skipped task labels and an Expert completed/total counter so handled checklist tasks cannot be mistaken for badge completion. Legacy skipped records cannot be automatically reclassified because their originating action was not stored.

When playlist.use is active, an acknowledged overlay.saved event must match the guided overlay ID, then adopts the actual saved playlistId and completes the task. A stale tutorial playlist ID must not block native Save completion. Another overlay, a foreign owner or a save without a playlist must not complete the active association task. The native editor's selection and Save behavior remain unchanged.

Explore adds explore.runners, account settings, AI connections and editors through four new explore.* tasks. Runner discovery highlights the native Runners tab and table, including the empty Free Runner state. Settings teaches avatar → My Settings → Settings; AI teaches avatar → My Settings → Connections. Resuming an inner checkpoint first reveals its owning Settings or Connections panel if another local settings tab is selected. Saved AI navigation checkpoints targeting the retired Settings location migrate to Connections. Editors teach the native Team tab and its overview. These tasks finish only through informational acknowledgement, never by provisioning, authorizing or inviting. Each remains separately started; earned Expert awards stay permanent when new guides are added.
