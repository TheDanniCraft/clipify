# Interaction contract

The launcher uses a HeroUI progress ring above the original feedback button. The checklist has a short title, four accordion sections and plain task rows. Only one section expands. A row is clickable across its title/action area; its checkbox shows completion or an indeterminate active state. Replay is an icon/action on that same row. No visible status subtitles, chooser control, completion card, persistent help paragraph or browser-storage footer. Guide copy uses no em dash.

A checkbox request opens a separate HeroUI popover anchored to it. Cancel and a second request do not change progress. Only confirmation records a manual skip; unchecking restores the task. Popover focus takes priority over deferred launcher focus.

Starting/replaying never changes pages. A task on another page highlights the actual Dashboard link, tab, edit control or app-menu action. Creation replay reaches Add Overlay, regardless of existing completion. Only the user's normal Add action creates a resource. Within a journey, successful steps continue naturally; informational acknowledgement of defaults records a skip. Native Save controls remain unchanged.

Consent settings hide/pause guidance. Expected preview/clip selectors temporarily suspend it. Native menus preserve their semantics and focus. Missing controls and unrelated navigation pause with a short recovery message, without returning the user to another page. Support introductions point to the real widgets; using one pauses the guide so its normal form/dialog remains usable.

Account progress persists in PostgreSQL. Browser clearing and reauthentication preserve completion, skips and minimization. Existing owned setup is recognized without showing a new-user popup. Clipboard success is required before external instructions; finishing them is self-reported learning completion, not verified delivery.

The launcher names the current or most recently active section and shows that section’s count when no task is running. Persist the section ID with account progress. Personalization contains filters before styling; retaining defaults records a skip. Starting styling inside Theme Studio begins at the editor. Resuming a styling checkpoint elsewhere highlights normal navigation through overlay settings and Customize Overlay Style before returning to that checkpoint. Save steps expose Back to review filters or styling, without changing the app’s Save action. Styling highlights the workspace including its live preview and summarizes color, font, component and effect controls rather than requiring every setting to be changed. Subtasks remain flat.
