# Auth Security and Privacy Inventory

This inventory is a release-controlled map of the authentication rewrite's security and personal-data stores. Values, credentials, tokens, OTPs, and message payloads are never retained in test evidence.

| Category            | Authoritative store                            | Data and purpose                                                                                                                  | Protection                                                                                                              | Retention and deletion processing                                                                                                                                                  |
| ------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sessions            | `auth.session`                                 | Revocable dashboard session token, account link, expiry, active organization, bounded IP/user-agent context                       | HTTP-only Better Auth cookie; database expiry/revocation; server-side account lifecycle checks                          | Expires or is revoked; all active sessions are revoked on suspension and identity deletion cascades remaining records                                                              |
| OAuth credentials   | `auth.account`                                 | Twitch subject, scopes, encrypted access/refresh/ID credentials, and expiry metadata                                              | Better Auth `encryptOAuthTokens`; provider subject uniqueness; serialized refresh; secrets excluded from audit/evidence | Retained while the provider account is connected; removed on disconnect or eligible identity purge, subject to provider revocation                                                 |
| Email OTPs          | `auth.verification`                            | Short-lived sign-in and verified-email challenge material                                                                         | Better Auth email-OTP attempt limits, expiry, configured protected storage, route rate limits, and no logging           | Expires after the configured OTP window and must be deleted after use/expiry cleanup                                                                                               |
| Passkeys            | `auth.passkey`                                 | Public key, credential ID, signature counter, device type, backup/transports metadata                                             | Origin/RP binding, replay and counter-regression checks; no private key is stored                                       | Retained until the user removes the credential or the identity is purged; removal must preserve another recovery path                                                              |
| Notification data   | `notification_outbox`                          | Recipient, template/version, locale, bounded secret-free payload, delivery state, dedupe key, provider message ID, redacted error | Payload schema checks reject secret-shaped keys; worker leases and idempotent dedupe; evidence is value-free            | Retained only for delivery/retry/dead-letter operations and support retention; personal recipient/payload data is removed during eligible purge                                    |
| Audit history       | `audit_events`                                 | Security action class, outcome/reason, actor/session/account references, correlation ID, bounded redacted metadata                | Append-only application flow; metadata type/size/secret checks; secret redaction before persistence                     | Security/legal retention policy applies; account purge retains only the minimal lawful tombstone and removes personal references where permitted                                   |
| Deletion processing | `account_deletion_requests` and purge manifest | Choice, lifecycle boundaries, actor/timestamps, redacted Stripe snapshot, optimistic version, recovery/purge result               | Owner + recent authentication; compare-and-set versioning; exact 30-day recovery boundary; secret-free snapshots        | Scheduled until paid-through/immediate suspension, recoverable for 30 days after actual suspension, then separately authorized idempotent purge with explicit retention exceptions |

## Release controls

- Stripe remains the authority for subscription and billing emails; Clipify sends lifecycle and capability notices only.
- Recovery links navigate to authenticated recovery and never authenticate the recipient.
- Backups are not restored automatically by deletion or migration tooling.
- The exact operational retention duration for audit and delivered/dead-letter notification records must be approved before production cutover; until then the release decision remains No-Go.
